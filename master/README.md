# MortalGIS master data and approval ledger

This folder decides which sources are allowed onto the map, and builds one DuckDB file that holds what the map shows today plus every value each staged source reported. The weekly build reads `ledger.csv` and nothing else from here. The DuckDB file is derived, is not in this repo, and is not on the map.

| File | What it is |
|---|---|
| `ledger.csv` | The approval ledger. One row per source, bundle and measure. **This is the file you edit.** |
| `sources_terms.csv` | Terms found for each source: status, page read, date, what the page said. Edit when you check a new source. |
| `schema.sql` | Every table and view, with comments. |
| `master.py` | `build` (make the DuckDB file), `ledger` (reload after editing), `check`, `export-json`, `stats`. Needs `duckdb`, `pandas`, `pyyaml`. Not used by the weekly workflow. |

## How a source reaches the map

1. In `ledger.csv`, set `status` to `approved` for a row and fill `approved_by` and `approved_on`. Do not touch the other columns; `master.py build` recomputes them and keeps what you typed in `status`, `approved_by`, `approved_on` and `note`.
2. For a staged state bundle, copy its file or files into `data_manual/states/` (the build reads them from there) and move its entry from `staging/sources_proposed.yml` into `pipeline/sources.yml`. If a row is approved and its file is missing, the build stops instead of filling from nothing.
3. `pipeline/build_data.py` reads a source only when its row is `approved` or `released`. That covers the live sources (Michigan, New York, New Mexico, Pennsylvania; bundle `live`) as well: set one to `held` and the build stops using it. A missing or malformed ledger stops the build.
4. The build still checks every source against CDC's published counts, with the same rule as before: at least 50 CDC-published county-years checked and at least 90% within max(2, 10%); a year under 80% agreement (at least 5 checked) is skipped. A staged row must also carry verdict `USE` in the ledger. Both checks have to pass.

What an approved row does to the map: it fills only cells CDC hides (count -1) with the state's exact 1–9 count. CDC wins on every cell it publishes. A filled cell shows its count and no rate (a rate on fewer than 20 deaths is not shown), gets the dashed outline, and names its source.

Not wired into the map yet: the 5-year totals in the NC bundle (an approved `nc_lcd_5yr` row is ignored and the build says so), which are loaded, checked and counted in the master file. The "1–4" bands from WISH, MICA, MSTAHRS and SCAN are on the map as a tooltip, panel chip and legend line (see "1-4 state bands on the map" below).

## Ledger vocabularies

- `status`: staged, approved, released, held, rejected, candidate, blocked, parked. `approved` and `released` are the two the build uses.
- `verdict` (automatic): USE, SKIP, NO_CDC_MEASURE, n/a.
- `terms_status`: stated, stated_review, none_stated, restricted, unchecked. `none_stated` means the page was read and says nothing; the source is used with attribution and flagged. `stated_review` means a stated term (a copyright notice, a disclaimer) that is not a bar on reuse but must be read before anything is uploaded; it is flagged `terms_stated_review`. A row whose terms are `unchecked` fails `master.py check` when approved.
- `warnings` never block: `wonder_9_or_fewer`, `rate_under_20`, `terms_none_stated`, `low_agreement_years`, `gate_sample_small`, `agreement_under_95`, `overlaps_other_bundle`, `review_before_use`, `x_cells_not_narrowable`, `band_only_1_4`, `state_total_off`, `spans_not_in_map`, `terms_stated_review`, `exact_match_under_80`, `band_years_unreliable`.
- `exact_pct` (automatic): of the county-years where CDC publishes a count of 10 to 19, the share the state reproduces exactly. The agreement gate allows max(2, 10%), so a source can pass it while being off by one or two in small counties, which is where fills live. `exact_match_under_80` warns below 80% (at least 100 samples).

## State-total check (a second anchor besides CDC's county counts)

The county gate only sees counties where CDC publishes 10 or more, so it cannot see the small counties it exists to fill. The state-total check adds up each bundle's county counts for a year and compares them with CDC WONDER's state total (summed from `site/data/state_month`), and with the state's own printed total where the bundle has one (IL, MO, WI, NC). It is coverage-aware: counties a bundle says nothing about explain a shortfall, so a shortfall is judged only when every county is accounted for. Over the reference is always judged.

Tolerance is max(2, 2%) against WONDER and max(2, 0.1%) above the state's own total. Today `state_totals` holds 3,612 state-years; 3,079 have a reference to compare against and 108 are flagged `state_total_off` (ledger columns `anchor_n`, `anchor_off_n`, `anchor_off_years`). 93 are shortfalls (2% to 100% below WONDER, 16 of them over 5%) and 15 are above the reference (2% to 7%). Georgia has 61 of 343 compared (median 2.7% short), Maryland 9 of 161, Mississippi 5 of 369, Alabama 4 of 83 (firearm 2015 to 2018, all zeros), Florida 3 of 182 (2000, over), South Carolina 0 of 319. Warnings only; nothing is blocked. It also confirmed that a county gate pass is not enough on its own: Missouri's derived firearm series passes the county gate yet covers a fraction of the state, which the check reads as partial coverage rather than a failure.
